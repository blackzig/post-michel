# Engenharia de Software para Mentores — Trilha de Formação

Dominar um assunto para orientar outras pessoas exige quatro capacidades: **compreender, executar, explicar e avaliar**. Esta trilha desenvolve essas capacidades em Engenharia de Software, conectando conhecimento técnico à condução de mentorias.

O objetivo é ajudar o mentorado a construir autonomia. A formação não estabelece prazo garantido para contratação, não substitui experiência profissional e não equivale a uma certificação.

## 1. Como estudar

Cada lição deverá conter fundamentos, um exemplo aplicado, perguntas de diagnóstico, exercícios, critérios de conclusão e fontes. Estude uma lição, produza a entrega e explique suas decisões antes de avançar. Se houver lacunas, repita a prática com um problema diferente.

O tempo depende do ponto de partida. Uma pessoa experiente pode acelerar exercícios básicos; alguém iniciante pode precisar dividir uma lição em vários encontros. Quantidade de vídeos assistidos não será critério de domínio.

## 4. Projeto que acompanhará a trilha

Usaremos um **sistema fictício de agendamento de mentorias**. A primeira versão terá cadastro de horários, reserva e cancelamento. Novas necessidades serão introduzidas de forma gradual: prevenção de reservas concorrentes, persistência, autenticação, testes, entrega e monitoramento.

O laboratório usará dados inventados. Não é necessário publicar dados de pessoas reais para demonstrar competência.

A linguagem será escolhida conforme a etapa e o objetivo do estudante. Java pode servir como implementação de referência para quem já atua nesse ecossistema, mas os conceitos precisam ser explicáveis também sem depender de um framework.

## 5. Critério de domínio

Para cada competência, procure evidências de que o estudante:

- explica o problema e suas restrições;
- realiza uma tarefa proporcional ao seu nível;
- verifica o resultado e investiga falhas;
- justifica uma escolha e reconhece uma alternativa;
- adapta a solução quando uma condição muda.

Para o mentor, acrescente: consegue fazer perguntas úteis, oferecer feedback específico e definir um próximo exercício sem retirar a autonomia da pessoa?

Esta é uma rubrica didática própria. Não deve ser usada como certificação, classificação universal de senioridade ou previsão de contratação.

## 6. Fontes de orientação

O [SWEBOK, da IEEE Computer Society](https://www.computer.org/education/bodies-of-knowledge/software-engineering), organiza áreas de conhecimento da disciplina. Ele é uma referência de abrangência, não um roteiro obrigatório para entrevistas ou uma lista que todo iniciante deva dominar antes de procurar oportunidades.

Os [princípios do Manifesto Ágil](https://agilemanifesto.org/iso/ptbr/principles.html) ajudam a discutir entregas frequentes, colaboração e melhoria do trabalho.

A sequência, os exercícios e os critérios desta trilha são propostas didáticas originais. Fontes e documentação específicas serão consultadas em cada tema.
